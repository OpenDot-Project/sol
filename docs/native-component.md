# Native component packaging

This page describes unreleased source development. Published Sol 0.0.1 remains the initial CST
frontend. A development archive does not publish or replace that release.

After `eng/build-backend.ps1`, run
`eng/package.ps1 -IncludeNative -OutputDirectory out/packages/native` to assemble Solc with its
private .NET 10 runtime, managed frontend, LLVM/LLD component, ORC hosts and SolRT. The ordinary
package command still produces the smaller frontend component. Native Windows CI qualifies and
uploads the additional archive.

The ordinary archive is `sol-<version>-windows-x86_64.zip`; `-IncludeNative` produces
`sol-<version>-windows-x86_64-native.zip`. Each has its own matching checksum and root directory.

## Payload and integrity

The launcher remains `bin/solc.exe`, the framework-dependent payload is under `managed`, and the
private .NET runtime lives under `runtime`. The native package adds `managed/native`:

| File | Purpose |
|---|---|
| `OpenDot.Sol.LlvmBridge.dll` | Thin C++/CLI adapter. |
| `OpenDot.Sol.LlvmNative.dll` | LLVM 23.1.3 C++ API with embedded LLD.COFF/LLD.Common. |
| `ijwhost.dll` | .NET mixed-mode hosting support. |
| `sol-exec-host.exe` | Isolated ORC guest using dynamic SolRT. |
| `sol-exec-host-static.exe` | Isolated ORC guest using static SolRT. |
| `SolRT.dll`, `SolRT.lib` | Guest runtime DLL and import library. |
| `SolRT-static.lib` | Static guest runtime. |
| `backend.json` | LLVM/runtime ABI, build toolset, dependencies and prerequisites. |

An explicit allowlist excludes native PDBs, build intermediates, SDK headers/libraries, external
linker executables and the development machine's `link-paths.txt`. Guest Yellow Tea remains in
the native application process, separate from the compiler's CLR heap.

`component.json` inventories every payload file's size and SHA-256 digest, excluding itself.
ZIP timestamps are normalized; an adjacent `.sha256` identifies the archive. These hashes are
not signatures or publisher provenance. `eng/verify-component.ps1` checks identities, size bounds,
duplicate/private paths, exact inventory membership and digests without extracting or executing
the archive. Package assembly removes its own generated staging tree after closing all handles.

## Installed prerequisites

The component supplies .NET 10; it does not need a system .NET runtime or SDK. Its C++/CLI adapter
needs a compatible Microsoft Visual C++ v14 **x64** Redistributable. `backend.json` records the
MSVC toolset used to build the adapter. Follow Microsoft's
[supported Redistributable guidance](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist).
The current package does not install that prerequisite automatically.

ORC, static archives and Sol containers do not require Windows SDK search paths or installed LLVM
tools. AOT EXE/DLL linking additionally requires MSVC x64 C++ build libraries and the Windows SDK.
Run Solc from an x64 Visual Studio developer shell whose `LIB` environment names those installed
directories. Missing libraries produce an explanatory error before an output is committed.
Embedded LLD performs the link; no linker executable is launched.

Local development backends may supply `link-paths.txt`, generated by `build-backend.ps1`.
That explicit file takes precedence over `LIB`; it is omitted from the distribution. Relative
library paths are rejected. Windows SDK libraries are not copied into the archive.
An empty or whitespace-only `SOLC_NATIVE_ROOT` override uses the packaged backend location.

## Notices and qualification

The .NET runtime retains its upstream notices. `licenses/native` adds digest-pinned LLVM/LLD
23.1.3 license texts and the statically linked zlib, zstd and libxml2 copyright notices. Metadata
records port versions, vcpkg binary ABI identities and the pinned source commit. This inventory
is not an SPDX 3.x SBOM or an advisory scan.

Native package smoke copies the component into a path containing spaces and Unicode, removes
LLVM/system .NET/development-backend overrides, and restricts `PATH` to Windows System32.
It checks both ORC modes, SDK-independent archives/containers, missing-SDK rejection and AOT
EXE/DLL production using an explicit developer-shell `LIB`. Generated String/array/GC programs
run with checked UTF-8 output. This is relocation/environment isolation on a build machine,
not clean-VM installation qualification or a promise covering all Windows versions.

See [native lowering](fir-native.md), [library artifacts](library-artifacts.md) and
[current Yellow Tea](yellow-tea/current-implementation.md) for language/runtime limitations.
